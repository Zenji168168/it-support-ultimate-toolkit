⚠️ កុំប្រើ 40 MHz width លើ 2.4GHz ក្នុងអគារ ឬការិយាល័យ ព្រោះវាបណ្តាលឱ្យ Co-Channel Interference ធ្ងន់ធ្ងរ!

🚀 5 GHz Spectrum (High Throughput)

UNII-2e (DFS) : 100 to 144 (Enterprise)
UNII-3 (High) : 149, 153, 157, 161, 165

1. NAT Port Forwarding (Port Forward)

ចូលទៅកាន់ Firewall > NAT > Port Forward > Add:

  • Interface: WAN
  • Address Family: IPv4 | Protocol: TCP
  • Destination: WAN address
  • Destination port range: From: 443 To: 443 (ឬ Custom Port)
  • Redirect target IP: 192.168.1.50 (Internal Server)
  • Filter rule association: Add associated filter rule (បង្កើត Rule ស្វ័យប្រវត្តិ)

2. Multi-WAN Gateway Failover (Auto Fallback)

ចូលទៅកាន់ System > Routing > Gateway Groups > Add:

  • Group Name: GW_FAILOVER
  • WAN1_GW: Tier 1 (Primary ISP)
  • WAN2_GW: Tier 2 (Backup ISP)
  • Trigger Level: Member Down (Packet Loss > 20% ឬ High Latency)
  • កំណត់នៅក្នុង Firewall > Rules > LAN > Default Allow Rule > Advanced > Gateway ជ្រើសរើស GW_FAILOVER។

Incident SOP 01 Network Protocol

🌐 SOP: Network Drops & "Unidentified Network / No Internet" Fix

មគ្គុទ្ទេសក៍ដោះស្រាយរហ័សជាប្រព័ន្ធ 5 ជំហាន (OSI Layer Troubleshooting) ពេលកុំព្យូទ័រដាច់អ៊ីនធឺណិត ឬជាប់សញ្ញាឧទានពណ៌លឿង (Yellow Exclamation Mark)។

📋 5-Step Diagnostic Workflow:

  1. Physical Link Check: ពិនិត្យភ្លើង LED លើរន្ធ RJ45 (បៃតង/ទឹកក្រូច)។ បើគ្មានភ្លើង = ខ្សែដាច់, ដោត switch មិនដល់, ឬកាត network ខូច។
  2. IP Address Verification: រត់ ipconfig។ ប្រសិនបើ IP ចាប់ផ្តើមដោយ 169.254.x.x (APIPA) = មិនទទួលបាន IP ពី DHCP Server (ពិនិត្យខ្សែ, DHCP Pool ពេញ, ឬ VLAN ខុស)។
  3. Default Gateway Ping: ping 192.168.1.1។ បើ ping មិនឆ្លើយតប = បញ្ហាក្នុង Local Network (Switch/Router LAN Port)។
  4. External IP Ping (Bypass DNS): ping 8.8.8.8 ឬ ping 1.1.1.1។ បើ ping ស្គាល់ ប៉ុន្តែបើក Web មិនចេញ = បញ្ហា DNS Resolution!
  5. DNS Resolution Check: nslookup google.com។ បើ timeout ត្រូវដូរ DNS ទៅ 1.1.1.1 ឬ 8.8.8.8។
Incident SOP 02 Printing Subsystem

🖨️ SOP: Network Printer Offline & Stuck Spooler Queue Playbook

ដោះស្រាយជាស្ថាពរនូវបញ្ហា Printer បង្ហាញ Offline ជាប់រហូត, ចុច Print មិនចេញ, និង Print Job ជាប់គាំងលុបមិនទៅ។

⚠️ មូលហេតុចម្បងដែល Printer បង្ហាញ Offline លើ Windows 10/11:

1. WSD (Web Services for Devices) Port Bug: Windows ប្រើ WSD Port ដោយស្វ័យប្រវត្តិ។ ពេល Printer ចូល Sleep Mode, Windows គិតថា Printer ដាច់ ហើយប្តូរ Status ទៅ Offline ជាប់រហូត។
2. SNMP Status Enabled Bug: នៅក្នុង Printer Port Properties, ប្រសិនបើធីក "SNMP Status Enabled" ហើយ Network បិទ SNMP UDP 161, Windows នឹងចាត់ទុក Printer Offline។

🛠️ ដំណោះស្រាយជាស្ថាពរ (Permanent Fix):

  1. ចូល Control Panel > Devices and Printers > Right Click លើ Printer > Printer properties។
  2. ចូល Tab Ports > ចុច Add Port... > ជ្រើសរើស Standard TCP/IP Port > New Port...។
  3. បញ្ចូល IP ថេររបស់ Printer (ឧ. 192.168.1.200) > Finish។
  4. ចុច Configure Port... > ដោះធីក (Uncheck) "SNMP Status Enabled" > ចុច OK។ នោះ Printer នឹង Online ជានិច្ច!
Incident SOP 03 Crash Kernel Analysis

💻 SOP: Windows BSOD (Blue Screen) Analysis & Stop Code Playbook

វិធីសាស្ត្រពិនិត្យ Minidump File ស្វែងរក Driver/Hardware ដែលបង្កឱ្យគាំង Blue Screen និងដំណោះស្រាយលើ Stop Codes សំខាន់ៗ។

🔍 ការវិភាគ Minidump File តាម PowerShell:

# ពិនិត្យបញ្ជី Minidump files ក្នុងម៉ាស៊ីន:
Get-ChildItem -Path "C:\Windows\Minidump" -ErrorAction SilentlyContinue

# ពិនិត្យកូដ BugCheck Code ចុងក្រោយតាម Windows Event Viewer:
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WER-SystemErrorReporting'} -MaxEvents 5 | Format-List TimeCreated, Message
BSOD Stop Code មូលហេតុ (Likely Cause) វិធីដោះស្រាយ (Action)
DRIVER_IRQL_NOT_LESS_OR_EQUAL Driver Network, Wi-Fi ឬ Graphic ខូច Boot ចូល Safe Mode > ដំឡើង Driver ថ្មី ឬ Rollback Driver
PAGE_FAULT_IN_NONPAGED_AREA RAM ខូច ឬ Antivirus ប៉ះទង្គិច Kernel រត់ mdsched.exe (Windows Memory Diagnostic), ដោះ RAM ដុសជ័រលុប
INACCESSIBLE_BOOT_DEVICE ខូច BCD, ប្តូរ SATA Mode (AHCI/RAID) ចូល BIOS ពិនិត្យ SATA Mode (AHCI), រត់ bootrec /rebuildbcd
CRITICAL_PROCESS_DIED System file សំខាន់ៗរបស់ Windows ខូច រត់ DISM RestoreHealth & SFC Scannow (Script ខាងក្រោម)
Incident SOP 04 Performance Optimization

⚡ SOP: Windows 10/11 100% Disk Usage & High CPU / RAM Fix

ដោះស្រាយជាស្ថាពរនូវបញ្ហាម៉ាស៊ីនដំណើរការយឺតខ្លាំង (Sluggish), Task Manager បង្ហាញ Disk 100% ជាប់រហូត និង CPU ឡើងកម្តៅខ្លាំង។

🚀 4 ជំហានដោះស្រាយ 100% Disk Usage ដ៏មានប្រសិទ្ធភាពបំផុត:

  1. Disable SysMain (Superfetch): SysMain ព្យាយាម Preload ទិន្នន័យចូល RAM ដែលធ្វើឱ្យ Hard Disk ចាស់ៗ ឬ SSD មួយចំនួនឡើង Disk 100%។
  2. Clear Windows Update Cache: កាលណា Windows Update ទាញយក File ខូច វានឹងព្យាយាម install ម្តងហើយម្តងទៀតធ្វើឱ្យ CPU & Disk ជាប់គាំង។
  3. Adjust Virtual Memory (Pagefile): កុំទុកឱ្យ Windows Manage Pagefile ដោយស្វ័យប្រវត្តិលើ HDD យឺត (ត្រូវកំណត់ទំហំថេរ Initial = Maximum = 1.5x RAM)។
  4. Disable Connected User Experiences (Telemetry): កាត់បន្ថយ background background diagnostic tracking ឥតប្រយោជន៍។

Incident SOP 08 Mission Critical

🚨 SOP: Server RAID Array Degradation & Failed Disk Replacement

នីតិវិធីប្រតិបត្តិការស្តង់ដារ (SOP) ដោះស្រាយពេល Server ធ្លាក់ចូលស្ថានភាព RAID Degraded នៅលើ Dell PowerEdge (PERC) និង HPE ProLiant (Smart Array)។

🛑 ច្បាប់មាស (Golden Rules) ហាមដាច់ខាត:

  • ហាម Reboot Server ភ្លាមៗដោយគ្មានការពិនិត្យស្ថានភាព Controller ច្បាស់លាស់។
  • ហាមដក Drive ច្រើនជាង ១ គ្រាប់ក្នុងពេលតែមួយលើ RAID 5។
  • ហាមចុច "Clear Foreign Configuration" ប្រសិនបើ Disk ដែលទើបដោតចូលជា Disk ចាស់ដែលមាន Data សំខាន់។

📋 ជំហានផ្លាស់ប្តូរ Hard Drive ដែលខូច (Step-by-step Replacement):

  1. ចូលមើល Dell iDRAC / HPE iLO ឬ OpenManage OMSA ដើម្បីស្គាល់ Slot Number & Drive Serial Number ដែលខូច (ភ្លើង LED លើ Drive នឹងភ្លឹបភ្លែតពណ៌ទឹកក្រូច/Amber)។
  2. រៀបចំ Drive ថ្មីដែលមានទំហំស្មើ ឬធំជាង Drive ចាស់ និងមាន Bus Speed (12Gbps SAS ឬ 6Gbps SATA) ដូចគ្នា។
  3. ដក Drive ចាស់ដែលខូចចេញយឺតៗ (រង់ចាំ 30 វិនាទីឱ្យ Motor ឈប់វិល) រួចដោត Drive ថ្មីចូល។
  4. ស្ថានភាព Rebuild នឹងចាប់ផ្តើមដោយស្វ័យប្រវត្តិ (Auto Rebuild)។ ប្រសិនបើមិនចាប់ផ្តើមទេ ចូល iDRAC/PERC BIOS ហើយកំណត់ Drive ថ្មីជា "Dedicated Hot Spare" សម្រាប់ Virtual Disk នោះ។
Incident SOP 09 Emergency Security

☣️ SOP: Ransomware & Malware Incident Response Emergency Protocol

នីតិវិធីសង្គ្រោះបន្ទាន់ក្នុងរយៈពេល ១៥ នាទីដំបូង (Golden Hour) ពេលប្រទះឃើញមេរោគជំរិតទារប្រាក់ (Ransomware) វាយលុកក្នុងប្រព័ន្ធបណ្តាញក្រុមហ៊ុន។

🚨 ដំណាក់កាលទី ១: កាត់ផ្តាច់ការចម្លងជាបន្ទាន់ (Containment 0 - 15 Mins):

  1. ដកខ្សែបណ្តាញ (Ethernet) & បិទ Wi-Fi ភ្លាមៗ: ហាម Shut down ម៉ាស៊ីន (ការ Shut down អាចបំផ្លាញ Volatile RAM Evidence និង Encryption Keys ដែលអាចសង្គ្រោះបានក្នុង Memory)។
  2. ផ្តាច់ Network Shared Folders / NAS: ដកខ្សែបណ្តាញចេញពី Storage Server និង NAS ភ្លាមៗ ដើម្បីកុំឱ្យមេរោគ Encrypt ឆ្លងតាម SMB Share។
  3. បិទ Account Active Directory: បិទគណនី User ដែលរងគ្រោះដើម្បីទប់ស្កាត់ Lateral Movement។

🛡️ ការស្វែងរក Shadow Copies & ពិនិត្យការខូចខាត:

# ពិនិត្យមើលថាតើ Volume Shadow Copies នៅសល់ឬអត់ (Admin CMD):
vssadmin list shadows

# ពិនិត្យមើល Network Connections សង្ស័យដែលកំពុងភ្ជាប់ទៅក្រៅ:
netstat -ano | findstr /i "ESTABLISHED"

# ពិនិត្យ Process មិនប្រក្រតីដែលស៊ី CPU ខ្ពស់:
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10

# ពិនិត្យស្ថានភាពចាក់សោររបស់ Drive C:
manage-bde -status C:

# ដោះសោរដោយប្រើលេខកូដ 48 ខ្ទង់:

# ដក BitLocker Protection ជាបណ្តោះអាសន្នដើម្បីកុំឱ្យទារទៀត:
manage-bde -protectors -disable C:

វិធានការសង្គ្រោះបន្ទាន់កម្រិតខ្ពស់បំផុតពេលក្រុមហ៊ុនរងការវាយប្រហារដោយមេរោគជម្រិតទារប្រាក់ (Ransomware) ដើម្បីទប់ស្កាត់ការឆ្លងរាលដាល និងរក្សាភស្តុតាងសង្គ្រោះទិន្នន័យ។

🚨 ដំណាក់កាលទី ១: ផ្តាច់ប្រព័ន្ធភ្លាមៗ (First 5 Minutes)

1. ដកខ្សែបណ្តាញ Network (LAN) និងបិទ Wi-Fi ភ្លាមៗ ចំពោះម៉ាស៊ីនណាដែលសង្ស័យថាបានឆ្លង។
2. ដាច់ខាតកុំ Shutdown ឬបិទភ្លើងកុំព្យូទ័រ! ការបិទម៉ាស៊ីននឹងធ្វើឱ្យបាត់បង់ទិន្នន័យ Encryption Keys ក្នុង RAM Memory ដែលអ្នកជំនាញអាចទាញយកបាន។
3. ផ្តាច់ Core Switch / VLAN Isolation: ផ្តាច់ Port ឬបិទ Interface Switch ដែលភ្ជាប់ទៅកាន់ Backup Storage និង NAS ជាបន្ទាន់!

🔍 ដំណាក់កាលទី ២: ស្វែងរកប្រភពដើម (Identify Patient Zero)

1. ពិនិត្យ File Ownership លើ Shared Folder ដើម្បីដឹងថា User ណាជាអ្នកបង្កើតឯកសារ README_RECOVER.txt ចុងក្រោយ។
2. ពិនិត្យមើល Security Event Log ID 4624 (Logon Type 10 = RDP, Type 3 = Network SMB) លើ Domain Controller។

🛡️ ដំណាក់កាលទី ៣: ស្រង់ទិន្នន័យពី Immutable Backup

1. ផ្ទៀងផ្ទាត់កាលបរិច្ឆេទនៃ Backup ចុងក្រោយដែលមិនទាន់ឆ្លងមេរោគ (Clean Restore Point)។
2. Format ម៉ាស៊ីនដែលឆ្លងចោលទាំងស្រុង (Clean Wipe) មុនពេល Restore ទិន្នន័យត្រឡប់មកវិញ។
Business Continuity DR & RTO/RPO

💾 Disaster Recovery, 3-2-1-1-0 Backup Rule & Restoration Protocol

ស្តង់ដារគ្រប់គ្រងប្រព័ន្ធចម្លងទិន្នន័យបម្រុង (Backup) ធានាការបន្តអាជីវកម្មដោយគ្មានការរំខាន គណនា RTO (Recovery Time Objective) និង RPO (Recovery Point Objective) ត្រឹមត្រូវ។

🌟 The Modern 3-2-1-1-0 Enterprise Backup Rule:
  • 3 ច្បាប់ចម្លងទិន្នន័យផ្សេងគ្នា (1 Primary Production + 2 Backup Copies)
  • 2 ប្រភេទមេឌៀខុសគ្នា (Disk Storage + NAS / LTO Tape / Cloud)
  • 1 ច្បាប់ចម្លងត្រូវបានរក្សាទុកនៅទីតាំងផ្សេងពីក្រុមហ៊ុន (Offsite Location)
  • 1 ច្បាប់ចម្លងដាច់ខាតត្រូវតែជាប្រភេទ Immutable / Air-gapped (មិនអាចកែប្រែ ឬលុបបានទោះបីត្រូវ Hacker វាយប្រហារក៏ដោយ)
  • 0 កំហុសបន្ទាប់ពីការធ្វើតេស្ត Restore សាកល្បងជាប្រចាំខែ (Zero Recovery Errors)

ការពារកុំឱ្យ Email ក្រុមហ៊ុនធ្លាក់ចូល Spam / Junk របស់ដៃគូ (Gmail, Yahoo, Outlook 2024 Guidelines) តាមរយៈការកំណត់កំណត់ត្រា DNS: SPF, DKIM 2048-bit, និង DMARC Policy ត្រឹមត្រូវ។

1. SPF Record (DNS TXT លើ Root Domain):
v=spf1 include:_spf.google.com include:spf.protection.outlook.com ip4:203.144.10.5 ~all
(កំណត់ server ណាខ្លះដែលមានសិទ្ធិផ្ញើ email ក្នុងនាម domain របស់អ្នក)
2. DKIM Record (DNS CNAME / TXT ជាមួយ Selector):
selector1._domainkey.company.com CNAME selector1-company-com._domainkey.protection.outlook.com
(បោះត្រាហត្ថលេខាឌីជីថលលើសារ email បញ្ជាក់ថាខ្លឹមសារមិនត្រូវបានកែប្រែ)
3. DMARC Policy Record (DNS TXT លើ _dmarc.company.com):
v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc-reports@company.com; aspf=r; adkim=r
(បញ្ជាឱ្យ server អ្នកទទួលទម្លាក់ចូល Junk ឬ Reject ប្រសិនបើរកឃើញ email ក្លែងបន្លំឈ្មោះក្រុមហ៊ុន)
